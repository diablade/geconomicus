# Auto Seizure: a backend timer, and prison on an empty hand, not an unpaid debt

Auto Seizure is a new rule (`rules.autoSeizure`), **independent of `autoBank`**, that automates the debt game's collections side: when a credit reaches `FAULT`, instead of waiting on the animator's manual seizure dialog, a real **backend** 10s one-shot timer (same family as `CreditTimerManager`/`PrisonTimerManager`) starts the moment a player's fault-count goes 0→1. When it fires, the backend — never the client — settles every credit currently in `FAULT` for that player in one batch, **FIFO** (oldest fault first), against one shared, draining pool of coins and cards, using the same Seizure math (coins first, then cards honoring the game's `seizureType`/Decote/Fees) the manual dialog already uses. Cards are taken biggest-fits-without-overshoot first; once none fit without overshooting, the smallest overshooting card closes the gap, minimizing waste. **Prison then triggers whenever the player's hand ends up empty — regardless of whether the debt was fully covered** — with duration `round(1 + (timerPrisonMax−1) × shortfallRatio)` off the aggregate shortfall across the batch. Both this path and the existing manual path now end in a new tap-to-dismiss **Seizure Confirmation** dialog on the player's device; prison lockout begins once it's dismissed.

## Considered options

- **Client-cosmetic 10s spinner, backend resolves instantly** — the initial design. Rejected once the seizure math grew real (FIFO batching, Decote/Fees, the prison formula): resolving instantly server-side while the client fakes suspense either leaks the outcome early to a refresh or a second observer (animator table view), or requires re-deriving the same "don't reveal yet" logic the backend timer gets for free. A real backend timer reuses existing pause/resume (`IO.GAME.PAUSED`) and reconnect-safety infrastructure with no extra work.
- **Prison only when the debt is left unpaid** — the initial framing ("not fully reimbursed AND nothing left to seize"). Rejected/refined: prison release (`_releasePlayer`) unconditionally deals 4 fresh cards, so it's the *only* path back to a non-empty hand. Leaving a player with an empty hand but no prison (because they happened to pay off the last of their debt with their very last card) would strand them with nothing to play. Prison is therefore keyed on "hand is empty," not "debt is unpaid" — the two usually coincide but not always.
- **Never-overshoot card selection**, matching the existing `_seizeCards` helper used by death seizure (skips any card bigger than the remaining amount owed, which can under-collect even when the hand's total value would have covered the debt). Rejected for Auto Seizure in favor of biggest-fits-without-overshoot-first, then smallest-overshoot-to-close — this satisfies "prioritize big cards" while still minimizing how much the final card overshoots by.
- **One shared `autoBank` toggle** for both lending and collections automation. Rejected in favor of a separate `autoSeizure` toggle, so an animator can mix manual lending with auto collections, or the reverse.
- **A timer/overlay per credit** rather than per player. Rejected: the Fault Lockout overlay is already a single boolean across all of a player's credits (`credits.some(fault)`), not per-credit, and two full-screen overlays can't sensibly stack anyway. One 10s timer, scoped to the player, resolves every currently-faulted credit at once.

## Consequences

- No new rules fields beyond the `autoSeizure` toggle itself — duration, Decote/Fees, and the prison cap all reuse `rules.timerPrison` / `rules.seizureType` / `seizureDecote` / `seizureCost` exactly as manual seizure does today.
- The manual **Seize** action stays available on the Credit Chip menu at all times, as a fallback if Auto Seizure doesn't behave as expected — mirroring how Auto-Bank's manual contract dialog stays available in every mode.
- The 10s deadline is **not** reset if a second credit faults while the timer is already running; only the first 0→1 transition starts the clock, and later faults are simply swept into the same batch when it fires.
- FIFO ordering means an older fault is always paid off before a newer one; a newer credit can end up entirely unpaid despite the player holding assets, if those assets were already spent settling the older fault first.
- The new **Seizure Confirmation** dialog is a behavior change for the *existing* manual path too — today it silently reconciles coins/cards with no acknowledgment; both paths now converge on the same tap-to-dismiss result screen. The only remaining difference between manual and auto is the Fault Lockout overlay's wait-text ("go see the animator" vs. "seizure ongoing").
