# Results reads two sources by role, and events carry Last-Known values keyed by playerStateIdx

The v2 results page (`results/:sessionId`) computed everything by folding the raw event stream, using stored Last-Known values "when present and falling back to reconstruction when absent". In practice nothing was present: the `LkSnapshot` interface was a wish list guarded by a `TODO(back)`, the few places the backend did write LK used different names (`coinsLK` / `currentMassMonetary` against the front's `emitterCoinsLK` / `massMonetaryLK`), and the fallback silently produced confident wrong numbers — second lives were dropped entirely, production and seizure pushed zero deltas, and `CREDIT_SEIZURE` / `PLAYER_BIRTH` attributed a player's values to the Bank or the animator because their `emitter`/`receiver` orientation is inverted relative to `PLAYER_DIED`. The decision: give the two data sources **distinct roles**, make LK a real contract **keyed by `playerStateIdx`**, sample aggregate indicators only on the events that move them, and **delete the fold**.

## Source roles

- **gameState** (both games fetched alongside the session) is authoritative for every end-state number: each Life's final coins and cards, its status, and therefore the podium, the Gini and Ghost Money. It is also the registry of Lives — `playersStates[]` carries `{ idx, avatarIdx, status }`, which is the only reliable way to know that a reincarnated life exists, since `playerStateIndexSeq` starts above `avatarIndexSeq` and reincarnated lives have an `idx` no avatar shares.
- **The persisted event stream** supplies only what varies over time: the curves.
- **The survey answers** supply the feelings radar, and arrive late — a player may still be filling their survey after the session is closed, so the radar rebuilds on `IO.SESSION.NEW_FEEDBACK` rather than snapshotting at load.

A gap in the event stream can therefore distort a curve but can never corrupt a headline figure. Because the two sources can disagree, the page carries a permanent **Data Health Block** comparing each indicator's last sample and each Life's last curve point against the authoritative values, by exact integer equality.

## The LK contract

Every event that touches a life carries `playersLK` keyed by `playerStateIdx` — coins, card value, and (debt game) outstanding debt — mirroring the shape `PLAYER_STATE_SYNC` already uses on the `table` room per ADR-0008, so the stored stream and the live stream finally agree. `emitter` and `receiver` survive as **role pointers only** (who acted upon whom, for the events log and activity counts) and carry no values.

Aggregate indicators are LK-stamped only on their **concerned events** — the ones that actually move them. A transaction moves coins between players without changing the money mass, so sampling the mass there would add a vertex carrying no information. Every indicator is a step function and is rendered stepped, never interpolated.

## Considered options

- **Stamp every event with a full indicators block.** Rejected: it writes ~7 redundant numbers per row, and the sparse form yields exactly the step function's true vertices. Accepted cost of rejecting it — the set of concerned events is defined *by* the indicator set, so introducing a new indicator means re-auditing the event map, and games recorded earlier hold no samples for it. This cost applies only to indicators with **no per-life source**, such as the bank counters. Anything that is a sum over lives — goods in play, ghost money, average money per player, total debt — is derivable in the front from the per-life LK the contract already requires, so it can be added at any time and needs no stamping of its own.
- **Fill in the `LkSnapshot` TODO per call site, keeping side-keyed names.** Rejected: side-naming is ambiguous by construction whenever a counterparty is `BANK` or `MASTER`, which is exactly where the live bugs were. Fixing the two known inversions would not stop the third.
- **Emit aggregates as their own periodic indicator event.** Rejected: a second stream to keep in sync, and indicator points would no longer align with the events that caused them.
- **Keep the fold as a documented fallback**, or **backfill LK by replaying stored streams**. Both rejected: nothing is in production yet, so there is no historical data to protect, and a fallback that renders plausible wrong numbers is what hid every defect listed above. A backfill would additionally have to re-implement every game rule in a second place — the front/back drift the design set out to avoid.
- **Elapsed-time x-axis** so the two games align. Rejected: the page compares them as two columns rather than overlaid, and wall-clock keeps every point traceable to a row in the events log.

## Consequences

- `FoldState` and the `startAmountCoins` / `firstDU` seed parameters are deleted from `SessionResultsService`.
- Backend LK still to add: `aliveCountLK` on `player-died` / `player-birth` (a reincarnating death leaves the count unchanged while a terminal one decrements it, so it is not safely derivable by pairing); coins and card value on `player-init` (the t0 anchor — without it a player who never trades has an empty series and is filtered out of the chart entirely); card value on `prison-ended` (release deals 4 fresh cards) and on `production` (whose payload is `{ newCards }` only, and which is the largest mover of hand value in the game); per-life outstanding debt, from which the aggregate total debt is a front-side sum.
- The inverted `emitter`/`receiver` on `PLAYER_BIRTH` and `CREDIT_SEIZURE` stop mattering for values, but are still corrected so the role pointers mean what they say.
- The contract is enforced twice: a declarative table in `shared/constants.ts` (`EVENT_LK_CONTRACT` / `EVENT_LK_EXEMPT`), and a guard in the two creation paths (`EventHelper.createEvent`, `EventService.postNow`) that throws when an event is built without its required keys. Enforcement is immediate rather than phased, so the suite stays red until the migration completes. `back/__test__/event-lk-contract.test.js` keeps the table exhaustive against `DB_EVENTS`; `back/__test__/event-lk-emission.test.js` invokes every emitting service for real so an event cannot pass by never being exercised.
- The guard also checks **event identity**, which uncovered a separate defect: `CREDIT_NEW`, `FREE_MONEY`, `CREDIT_CANCELED`, `CREDIT_SETTLED` and `CREDIT_EXTENDED` were built from `entry.sessionId` / `entry.gameStateId`, fields the `GameStateManager` entry (`{ gameState, rules, events }`) has never carried. All five were persisted with `undefined` identifiers, making the entire debt-game credit history unreachable by `getBySessionId` and invisible to the results filter. They must read `gameState.sessionId` and the gameStateId argument instead.
- Ghost Money and Ghost Cards, transaction and production counts, average money per player and goods in play are computed in the front from the stream; the rest are read from LK as-is.
- Activity counts and `mostActive` aggregate per **Avatar**, not per `playerStateIdx`, or a reincarnated player's activity splits in two. See ADR-0014.
